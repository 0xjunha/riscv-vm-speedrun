# RV32IM guest workspace

This Cargo workspace builds the bare-metal Rust programs used as benchmark
guests. The public guest programs run inside RV32IM VM implementations, with no OS.
The guest programs use `#![no_std]` and `#![no_main]` and cannot rely on normal startup, stdlib, stdout, or process exit of Rust.

`rv32im-guest` crate, `link.x` and Rust build script supports such missing functionalities for the guest runtime.

## VM boundary

The [execution environment interface](../../interface_specs/rv32im-eei.md) starts each ELF at its entry point with:

- `a0`: address of the read-only input bytes
- `a1`: input length
- `sp`: top of the guest stack

`link.x` makes `_start` the ELF entry point. The runtime's `_start` prepares the
global and stack pointers, then calls the `__guest_main` function generated by `guest_entry!`.
That function turns `a0` and `a1` into a Rust byte slice and calls the workload's `main(&[u8]) -> u32`.
The conversion is safe because the VM contract guarantees that the input range is readable.

Guests communicate with the VM through `ECALL`: `write_output` appends bytes to
the run output, and the workload's return value becomes the exit code. A panic
exits with code 101.

## Components

- `runtime/` is linked into every guest ELF and provides `_start`, `guest_entry!`,
  output, exit, and panic handling.
- `workloads/` contains the benchmark binaries and their shared input/output
  helpers.
- `link.x` defines the VM-compatible ELF layout: entry point, page-aligned
  executable/read-only/read-write segments, global pointer, and the image
  boundary before VM input memory.
- `workloads/build.rs` is a Cargo build script. For RISC-V builds, it passes
  `link.x` to the linker and asks Cargo to rebuild when the script changes. It
  does not run in the VM or generate benchmark inputs.
- `.cargo/config.toml` selects `riscv32im-unknown-none-elf` and supplies the
  bare-metal linker flags.
- `rust-toolchain.toml` pins Rust and installs the RV32IM target.
